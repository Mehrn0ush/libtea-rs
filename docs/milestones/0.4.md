## 0.4-1 purl parsing and canonicalization

- **Why:** There is no purl type; `validate_purl` only checks the `pkg:` prefix after Base64URL decoding.
- **Size:** M (about 1–2 weeks)
- **Gate:** spec
- **Depends on:** none
- **Acceptance criteria:**
  - [ ] a maintained purl crate (or a recorded decision to hand-roll) is chosen with `cargo deny` and MSRV 1.89 checked
  - [ ] library function turns a purl into a canonical TEI (`purl` type, Base64URL, no padding) and back
  - [ ] the official purl-spec test suite runs in CI against it; failures are listed, not hidden

## 0.4-2 Persistent ETag cache

- **Why:** ETags are returned but not stored; no cache.
- **Size:** L (more than 2 weeks)
- **Gate:** DevSecOps usability
- **Depends on:** 0.3-7
- **Acceptance criteria:**
  - [x] opt-in on-disk cache keyed by method, URL and a hash of origin and key id, storing ETag, Last-Modified and a body hash (F6; `docs/cache.md`)
  - [x] conditional requests; eviction by size and age; `Cache-Control: no-store` and `private` honored (`crates/tea-client/tests/cache.rs`)
  - [x] security review note: `docs/cache.md` threat model (directory permissions, poisoning, credentials never stored). Limit stated there: a cache writer who forges both an artifact and its metadata is not detected

## 0.4-3 Offline mode

- **Why:** Not available.
- **Size:** M (about 1–2 weeks)
- **Gate:** DevSecOps usability
- **Depends on:** 0.4-2
- **Acceptance criteria:**
  - [x] `--offline` / `ClientBuilder::offline(true)` serves only from the cache; any network need is `ClientError::Offline`. **Changed from the plan:** the lock is not an input; `sync --offline` rebuilds from cached responses
  - [x] tests assert the mock server received no request (`cache.rs`, `cache_cli.rs`)

## 0.4-4 Host allowlist

- **Why:** `DestinationPolicy` lists exceptions; it cannot say "only these hosts".
- **Size:** S (≤ 2 days)
- **Gate:** security
- **Depends on:** none
- **Acceptance criteria:**
  - [ ] `DestinationPolicy::only_hosts` (or equivalent) refuses every other host, including after redirects and from discovery
  - [ ] CLI `--allow-host`
  - [ ] tests for discovery pointing elsewhere and a redirect to another host

- **Why:** `grep -rni swid spec/vendor` finds nothing, so `swid` is not in the pinned registry; unknown types stay structurally valid.
- **Size:** S (≤ 2 days)
- **Gate:** spec
- **Depends on:** none
- **Acceptance criteria:**
  - [ ] `docs/specification-baseline.md` states it and a test pins that an unknown type such as `swid` parses and validates
